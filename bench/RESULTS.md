# Benchmark results

Generated by `make bench-replay` from `bench/data/raw/*.jsonl`. Do not
edit by hand. Every number below is recomputed from the raw per-call
rows on each run, and hand edits are silently overwritten.

**Dollars are derived, not billed.** Each figure is the substrate's
reported `input_tokens`/`output_tokens` for that call multiplied by the
price table in `bench/prices.py`, version:

> 2026-07-20 (Sonnet 5 intro rate, valid through 2026-08-31)

| Model | Input $/MTok | Output $/MTok |
|---|---|---|
| `claude-sonnet-5` | 2 | 10 |
| `claude-haiku-4-5-20251001` | 1 | 5 |

No invoice was consulted and no billing API was read. The substrate's
own `total_cost_usd` is recorded per row as
`substrate_reported_cost_usd` but is never the basis: it includes
auxiliary Claude Code calls the benchmark never requested, and
attributes some Haiku overhead to the Sonnet arm.

## 3. The mechanism

Ranked by how short the required answer actually is:

  MMLU-Pro (one option letter) < GSM8K (a number) < MBPP (a Python function)

Ranked by Haiku's measured mean output tokens:

  GSM8K (509.9) < MBPP (1414.2) < MMLU-Pro (2255.8)

The two orderings do not agree, and that disagreement is the finding.
The family demanding the *shortest* answer --- MMLU-Pro, where the
contract asks for a single letter --- drew the *highest* Haiku token
spend, higher even than writing a Python function. This is not a clean
reverse trend either: GSM8K sits in the middle by required answer length
and lowest by spend. The point is only that required output length does
not predict spend.

That rules out the obvious objection, "Haiku is only expensive
because it emits verbose output formats, and a stricter contract would
fix it." On MMLU-Pro the contract is as strict as a contract gets:
Sonnet complies in a 74.1-token mean, while
Haiku spends 2255.8. The excess is reasoning,
not formatting, and an output contract constrains the answer, not the
reasoning that precedes it.

## 4. What this does not show

Every conditional-accuracy interval in section 1 overlaps its
counterpart. At n=50 per family this data cannot distinguish the two
models' accuracy, and **no claim that Sonnet is more accurate than
Haiku is supported here**. The cost result stands independent of any
accuracy claim.

Parse failures are grader-regex misses, not model failures: GSM8K's
parser accepts only a bare number, so a correct `ANSWER: $70,000` or
`ANSWER: 160 minutes` fails, in both arms. MMLU-Pro's parser does not
strip markdown bold, so three `**ANSWER: X**` rows fail. Those calls
still spent real, correctly-counted tokens, so they remain in the cost
figures; they are excluded only from accuracy, which is why accuracy is
reported conditional on parsing.

Zero execution errors means no arm was advantaged by dropped calls.
Zero non-`end_turn` stop reasons means no arm's output tokens were
censored by truncation. The last column re-derives each row's dollar
figure from its token counts and compares it to the value stored when
the call was made. A non-zero count would mean the data was corrupted,
or that the price table changed under it.
